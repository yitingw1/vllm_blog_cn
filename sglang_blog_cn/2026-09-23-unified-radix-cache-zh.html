SGLang 统一 Radix Cache：用一棵树实现混合模型的前缀缓存

Unified Radix Cache in SGLang: one tree for hybrid model prefix caching

作者：SGLang 团队 发布日期：2026-09-23 查看英文原文

本文改编自 LMSYS 关于统一 Radix Cache 的文章。

背景

当前缀 token 相同时，前缀缓存可以复用 KV。在全注意力（full attention）模型中，后续请求能够直接复用已经缓存的前缀，只计算新增的 token。

混合模型同时使用三类数据，而它们的复用规则各不相同：FULL（全注意力）需要匹配前缀上的 KV；SWA（滑动窗口注意力，sliding window attention）需要复用边界之前的一段连续窗口；MAMBA 则需要该边界处循环状态的快照，也就是检查点（checkpoint）。

DeepSeek-V4 组合了 FULL 与 SWA，Kimi-K3 为其 KDA 循环状态组合了 FULL 与 MAMBA，Inkling 则同时使用三者。SGLang 在一棵共享树上处理这些组合，每个组件自行定义复用规则。

统一 Radix Cache

设计与机制

每个 radix 节点保存一段 token，并为每个组件提供一个槽位。FULL 和 SWA 槽位保存 KV 页索引；MAMBA 保存前缀终点处的检查点。SWA 必需窗口之外的数据可以继续留在缓存中，也可以独立淘汰；淘汰后会留下一个称为“墓碑”（tombstone）的空槽位。

各组件分别处理自身的节点拆分、插入、锁定和淘汰。回收节点中的部分 SWA 数据时，系统会先在保留边界处分裂节点。MAMBA 检查点仍位于原来的前缀终点；请求复用该检查点时，通过写时复制（copy-on-write）获得一份私有副本，然后继续更新自身状态。

安全复用边界

匹配过程沿已命中的路径向前遍历，每个组件都会在每个候选边界检查自身数据。每个候选边界都独立评估，计算从所有组件共同接受的最深边界继续执行。

跨内存层级的 HiCache

HiCache 将统一 Radix Cache 扩展到 GPU L1、主机内存 L2 和外部存储 L3。有关分层和数据传输机制，请参阅 SGLang 中的 HiCache。

组件与边车数据

DeepSeek-V4 的 FULL 和 SWA 使用彼此独立、由分配器映射的页索引。压缩 KV、索引器缓冲区和压缩器状态等辅助池作为边车数据（sidecar）：它们共享所属组件的索引和数据传输流程，其中三个跟随 FULL，两个跟随 SWA。

多轮基准测试

多轮对话会不断延长可复用的前缀。对比仅使用 L1、L1+L2，以及额外加入 500 GiB Mooncake L3 的配置后，DeepSeek-V4-Flash 在 L3 配置下的有效输入吞吐量达到 145.5K token/s，而仅使用 L1 时为 9.4K token/s；平均首 token 延迟（TTFT）保持在 9 秒以内。

会话感知淘汰

应用使用稳定的 session_id 标识同一段对话中的请求。SGLang 会跟踪该会话对缓存条目的引用；调用 /close_session 会删除这个会话的引用，共享前缀仍会保留其他会话的引用。

对于已解锁且可以淘汰的 FULL 条目，系统依次按照是否存在引用、引用计数和基础淘汰策略排序，通常会优先回收没有引用的数据。会话保留策略适用于 L1/L2；L3 的淘汰则由存储后端负责。

SWE-bench 结果

在 SWE-bench 上，与 HiRadixCache 和 LRU 相比，同时启用统一 Radix Cache 与会话感知淘汰后，DeepSeek-V4-Pro 的 TTFT 最多降低 11.0%，Qwen3.5-397B-A17B 最多降低 16.6%。

Rust 树核心

SGLang 使用 Rust 执行树遍历、锁记账和 LRU 更新，以降低调度器上的 CPU 开销。Python 负责物理 KV 分配和缓存编排，并把 Rust 返回的操作应用到各个池中。

Python 侧负责：

  • 请求到 token 的映射
  • 物理 KV 分配
  • 池操作与编排

Rust 侧负责：

  • radix 拓扑
  • 各组件的锁记账
  • 侵入式 LRU 链表
  • 淘汰遍历

仅支持 L1 的 Rust 原型 #29074 在一项 200 轮对话基准测试中，相比 Python 树将 SWA 的 TTFT 降低 38%，全注意力降低 10%，混合 SSM 降低 5%。

随后合入的 Rust TreeCore #32710 支持 FULL、SWA 和 MAMBA 的各种组合，并支持 HiCache。会话感知缓存目前仍使用 Python 树核心。
